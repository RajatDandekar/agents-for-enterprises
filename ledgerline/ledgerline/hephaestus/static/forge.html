4 · The Shield

A rule in the prompt, or a rule in the tool?

What you will learn: a rule in the prompt is a request to the model; a rule in the tool is code that refuses. Run the same attacks with the rule in each place and see which one holds, and which one travels with your tools to Claude.

Your rules

Validation at the door

Wrong types, blank fields, a code that does not look like a code: refused before Ledgerline is called. Set it per tool in The Anvil (Input schema); measure it in Production (Schema, Reliability).

Output capped, no secrets

The results carry only business fields: no passwords, no e-mail addresses, no tokens. Check with Production · Payload.

Who the tool is

Your tools act as Emma, with her limit (£250,000) and her permissions. Switch to the service account above and run the attacks again: Ledgerline's own checks no longer protect you.

5 · Connect to Claude

The same tools, another harness.

What you will learn: MCP is the plug. Your forge is an MCP server at your own address; Claude connects to it, lists your tools and calls them, in your sandbox, as Emma.

Your MCP address

The key in the address is your forge's password: anyone with it can use your tools in your sandbox. Do not post it in the class chat. No sign-in is needed (no OAuth).

claude.ai or Claude Desktop
  1. Settings → Connectors → Add custom connector.
  2. Name: Hephaestus. URL: your address above. Add.
  3. In a new chat, open the tools menu and switch Hephaestus on.
  4. Paste a question below. Allow the tool when Claude asks.

Custom connectors are not on every plan; on a Team or Enterprise plan an owner may have to allow them first. If you cannot add one, use Claude Code.

Claude Code
  1. Run the command in a terminal.
  2. Start claude, type /mcp: hephaestus should say connected.
  3. Paste a question below.

Remove it afterwards with claude mcp remove hephaestus.

Check it works
