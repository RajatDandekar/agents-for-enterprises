Ledgerline ERP 7.1.2 is a maintenance release issued on 18 March 2019 for all Ledgerline 7 customers[^r1]. It established the handling of legacy Ledgerline 6.x supplier records, preserving original code formats with locked identifiers across core services[^r2][^r3]. It also documented specific operational workarounds for continuous stationery print alignment, part master search indexing, and terminal cache behaviour during despatch note reprints[^r4][^r5][^r6].

## Changes
Supplier master codes transferred from Ledgerline 6.x retain their legacy format without alteration or automatic padding, and the system records 'MIGRATION' in the creator field for each converted entry[^r2]. In background application services, migrated supplier records are marked as imported entities, restricting subsequent manual alteration of the original code value while keeping everyday trading fields accessible[^r3].

## Effect at Northbridge
Migrated records in the [[data-supplier-master|supplier master]] retain their historical code structure, but original supplier codes cannot be changed manually once imported[^r2][^r3]. 

Staff printing the works order summary report to continuous stationery from the production module encounter right-shifted column alignments on the final page when sub-assemblies contain extended descriptions; users must preview the document and send output to a laser printer instead[^r4]. Generic searches on the main part master hesitate when the full initial text string is omitted because Ledgerline performs a full stock list scan rather than using the primary index[^r5]. Additionally, reprinting a carrier despatch note immediately after amending a delivery address retrieves stale address data from local terminal memory unless the despatch entry screen is closed completely before reprinting[^r6].
