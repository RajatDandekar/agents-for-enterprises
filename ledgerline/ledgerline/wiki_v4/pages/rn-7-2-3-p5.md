Ledgerline ERP 7.2.3-P5 is a maintenance patch released on 19 October 2026 with current status for all Ledgerline 7 customers across Manchester and Leeds sites [^r2]. Deployed at Northbridge on 20 October 2026 by [[user-jfletcher|Joanna Fletcher]], it introduces per-sign-in loading for parameter PUR.DIR_LIMIT and automates dangerous-goods service code printing on carrier labels [^r1][^r3][^r5]. The patch is in active production use today, with workarounds required for three known issues affecting print spooling, item search, and invoice matching [^r1][^r2][^r9][^r10][^r11].

## Changes

Revisions to system parameter PUR.DIR_LIMIT now take effect at each user's next sign-in rather than requiring core application service restarts, while active sessions continue enforcing previous thresholds [^r3]. External background integrations maintaining persistent database connections do not pick up updates to PUR.DIR_LIMIT automatically and must drop and recreate sessions or reconnect after adjustments are made [^r4].

Carrier labels printed at packing benches now automatically display the dangerous-goods service code in the service banner for consignments containing traction batteries or packaged power units [^r5]. The carrier setup configuration screen links the dangerous-goods classification on the sales item record directly to the logistics provider collection profile without requiring manual code entry by packing staff [^r6]. Middleware and external integrations that intercept sales despatch files must parse and deliver the dangerous-goods service indicator unaltered in the transport request payload [^r8].

Standard works order summary print spooling occasionally truncates long component descriptions along the right margin on dot-matrix and line printers at Manchester and Leeds, which can be temporarily resolved by adjusting print queue page width [^r9]. Inventory part master searches experience degraded response times when search criteria are left blank or queried across all item groupings simultaneously [^r10]. Matching an invoice against a completed goods received note occasionally triggers a spurious rounding prompt even when net totals agree, which accounts staff can bypass by confirming line items manually [^r11].

## Effect at Northbridge

Deployment of patch 7.2.3-P5 was approved under change request CR-2026-029 on 7 October 2026 and installed on 20 October 2026 by Joanna Fletcher [^r1][^r12].

Despatch clerks handling [[items-bat|traction batteries]] and packaged power units under [[sop-sal-001|sales despatch procedures]] must discard any pre-printed or queued consignment documentation generated prior to patch 7.2.3-P5 and reprint labels via the sales despatch screen to ensure the dangerous-goods code appears on the service banner [^r5][^r7]. Accounts payable personnel matching purchase invoices under [[sop-ap-001|SOP-AP-001]] must manually confirm line items when presented with false rounding prompts on agreeing totals [^r11]. System administrators adjusting purchasing thresholds under [[pol-pur-001|POL-PUR-001]] can rely on user re-login to apply PUR.DIR_LIMIT, but must restart persistent database sessions for background integrations [^r3][^r4].
