Ledgerline ERP 7.2.2 was released on 10 June 2024 as a maintenance release applicable across both the Manchester works and the Leeds warehouse [^r1]. It introduced configurable three-way matching parameters and lowered the default cycle-count tolerance value [^r2][^r3]. Several known issues introduced in this version affect assembly sheet printing, stock enquiry lookups, and invoice matching dialogues [^r6][^r7][^r8].

## Changes

The default cycle-count tolerance parameter `INV.CNT_TOL_PCT` was reduced from 2.0% to 1.5% by value, which prevents count postings exceeding this variance threshold under error [[err-cnt-0240|ERR-CNT-0240]] until a recount is completed [^r2]. In addition, three-way matching tolerances are no longer hardcoded into the system and are instead governed by configurable system parameters `AP.MATCH_TOL_PCT` and `AP.MATCH_TOL_ABS` [^r3].

## Effect at Northbridge

For inventory integrations submitting counted totals directly to the inventory service, any transaction rejected with [[err-cnt-0240|ERR-CNT-0240]] must be caught by middleware to isolate the affected tag or bin record and alert stock control rather than failing silently [^r4]. In accounts payable, automated invoice loaders pushing supplier invoices into Ledgerline ERP must rely on core system validation via `AP.MATCH_TOL_PCT` and `AP.MATCH_TOL_ABS` instead of running separate tolerance checks prior to import [^r5].

Three operational workarounds exist for known issues in this release:
* Assembly sheet print runs at the Manchester plant may insert premature page breaks across multiple operations, isolating the sign-off box on a trailing sheet [^r6].
* Stock enquiry lookups across Manchester and Leeds can experience delays when querying parts catalogues with large transaction histories, requiring users to narrow searches by warehouse location [^r7].
* Purchase invoice variance warning dialogues can appear hidden behind the main entry window during invoice matching, requiring finance clerks to minimise the primary view [^r8].
