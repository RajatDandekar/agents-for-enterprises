Ledgerline ERP 7.2.3-P4 is a vendor patch release issued on 14 September 2026 for Ledgerline 7 customers [^r3]. It introduces an optional certificate check on purchase order entry screen [[screen-pur-po-01|PUR-PO-01]] via system parameter `PUR.CERT_CHK`, warning [[w-sup-0207|W-SUP-0207]], and runtime filtering on purchasing certificate-expiry reports [^r4][^r5][^r7]. At Northbridge Cycles, the patch was installed on 20 September 2026, but the `PUR.CERT_CHK` setting remains disabled at `N` under Change Advisory Board decision [[decision-2026-10-07-cr-2026-031-cert-check|CR-2026-031]] pending a review in January 2027 [^r1][^r2][^r10].

## Changes

Patch 7.2.3-P4 provides an optional certificate validation on screen [[screen-pur-po-01|PUR-PO-01]] governed by configuration parameter `PUR.CERT_CHK`, which defaults to `N` upon installation [^r4]. When `PUR.CERT_CHK` is set to `Y`, saving a purchase order for an item configured with the lithium-cell flag prompts warning [[w-sup-0207|W-SUP-0207 UN38.3 CERTIFICATE MISSING OR EXPIRED]] if the supplier does not possess an active [[topic-un-38-3-certificates|UN 38.3 certificate]] covering the purchase order date [^r5]. This check validates solely against the certificate record's valid-to date in relation to the order date, does not prevent saving the purchase order, and does not enforce internal company rules regarding original issue dates or grace margins [^r6].

Additionally, the certificate-expiry report in the purchasing module was updated to accept a certificate type parameter at runtime via a drop-down list or blank selection for all records [^r7].

Reported known issues in 7.2.3-P4 include right-hand margin clipping on the dispatched orders summary report for long trading names, degraded search dialogue response times during broad supplier item lookups, and batch print queue status remaining pending despite successful printing during high Manchester-Leeds network traffic [^r8].

## Effect at Northbridge

[[user-jfletcher|Joanna Fletcher]] installed patch 7.2.3-P4 at Northbridge on 20 September 2026 under change NBC-2026-017, leaving `PUR.CERT_CHK` disabled at `N` [^r1]. On 7 October 2026, the Change Advisory Board formally reviewed the feature under CR-2026-031 and resolved not to activate `PUR.CERT_CHK` or warning [[w-sup-0207|W-SUP-0207]] on [[screen-pur-po-01|PUR-PO-01]] [^r2][^r9][^r10]. The parameter remains set to `N`, with a operational review planned for January 2027 [^r2][^r10].
