# A7 · Guard one agent of yours, then attack it

Lecture 7 · Guardrails and Red-Teaming · due before Lecture 9 · **100 points**

Take the agent you traced and tested in A6 (your A4 or A5 agent, or Ask Northbridge if you have none) and do for it what
we did for Ask Northbridge in class: put code between the model and its tools, add one guard that reads text, measure
that guard with four numbers, and attack the whole thing yourself. The four notebooks are your worked example, each built
step by step: `NB7a_guards`, `NB7b_detectors`, `NB7c_nemo_guardrails`, `NB7d_red_team`.

Hand in one notebook (or repository) with the code, the outputs it produced, and a short write-up (one page, plain words)
answering the questions in each part. For model calls, use your Argus key through Argus's gateway (press **Notebook key**
in Argus), or any key of your own; with neither, use the recorded runs in the notebooks and say so. The injection
classifier, Presidio and every guard in code need no key: they run on the Colab machine. Never paste a key into what you
hand in. Attack only your own agent in your own sandbox.

## Part 1 · Guards in code, at the tool (30 points)
1. (6) Write down, in one sentence each, the two actions your agent must never take wrongly (for example "save without a
   preview and a recorded yes", "approve for someone else", "send a message to an outside address"). For each, say which
   facts decide it, and where those facts live: your system of record, or the conversation's own record. If the only
   place the fact lives is the model's reply, pick a different rule.
2. (12) Two guards in code that run **before** the tool does (NB7a, section 2). Neither may read the model's words. Each
   refusal returns three things to the model in place of the tool's result: who refused, a reason, and a next step. Show
   one conversation in which your agent is refused, recovers, and then finishes the task the right way.
3. (6) Every guard decision, allowed or refused, appears as a row in the trace you built in A6. Include one screenshot or
   printed trace with the guard's row next to the tool call it judged.
4. (6) Test the guards with no model at all (NB7a, the last section): make the tool calls an attacker would want directly,
   with the guards off and on, and report which worked. Then test the other direction: three pieces of honest work that
   your guards must **allow**, at least one of them an odd but harmless path (a second preview, a changed date). If you
   find a false alarm in your own guard, show it and fix it: that earns the points, it does not lose them.

## Part 2 · One guard that reads text (20 points)
1. (6) Find the place where text written by someone outside comes into your agent: an e-mail, a document, a web page, a
   field in a record that a customer or supplier can edit. Show one piece of outside text that carries an instruction for
   the agent (your own poisoned invoice), and what your agent does with it when nothing is in the way.
2. (8) Put one model-based guard at that place: an injection classifier, Presidio, NeMo Guardrails, or your own check
   with a second model (one narrow question, the text handed over as data, a yes or no with one reason). Say in two lines
   why you chose it over the other three.
3. (6) Add the rule in code that stands behind it: after the turn has read outside text, nothing is saved and nothing
   leaves in that turn. Show the same poisoned text again with both in place, and say which of the two did the stopping.

## Part 3 · Measure the guard: four numbers (20 points)
1. (8) A labelled set of your own: 10 attacks and 10 ordinary inputs, each labelled by hand before you run anything. At
   least 3 of the ordinary ones must be tricky: honest work with words like "ignore", "override" or "disregard" in it.
2. (8) For your guard from Part 2 report the four numbers: **caught** (attacks stopped, of 10), **false alarms**
   (ordinary inputs stopped, of 10), **time added** (the middle value per check), **cost per check**. Print every miss
   and every false alarm word for word.
3. (4) Say where you would switch this guard on, and where you would not, and point to the number that decides it.

## Part 4 · A small red team (30 points)
1. (10) An attack library for your agent: 10 attacks, each one a message (or an outside text) plus a **success check
   written in code** that reads your system's state, the tool calls or the trace. No attack may be judged by a model.
   Give each attack a code from the OWASP Top 10 for Agentic Applications (2026) or the OWASP Top 10 for LLM Applications
   (2026). Group them by what the attacker wants.
2. (10) Run all ten in a fresh sandbox each, three ways: no guards, your code guards only, and code guards plus your
   Part 2 guard. Report the **attack success rate** for each (attacks that worked ÷ attacks tried), name every attack
   that got through, and say which guard stopped each of the others, or that the model itself declined. Report beside it
   how much honest work each setting stopped (your 10 ordinary inputs from Part 3).
3. (10) A red team from scratch (NB7d): an attacker model rewrites three of your attacks in at least three ways each
   (for example a different wording, a translation, a two-turn build-up), your agent answers each rewrite in a fresh
   sandbox, and the original attack's check decides. Report how many rewrites got through with the guards off and on,
   and print one rewrite in full. If one gets through your guards, add it to the library and say what you would change.

## How it is marked
- Each part: does it run, is it measured (not described), is the reasoning honest. A small, real, measured result beats a
  big claimed one.
- Report the price of every defence. An attack success rate with no false alarms beside it, or a "caught" figure with no
  time and cost, gets half marks for that item.
- Your own bugs count in your favour when you find them and say so: the first version of our own guard refused Emma's
  real yes, and we put that on a slide.
- Copying our Ask Northbridge results is not allowed; using our code as a starting point is encouraged (cite it).
