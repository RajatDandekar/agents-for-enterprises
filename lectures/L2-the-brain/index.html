Section 2 of 9 · Tokens
Last sectionThe model guesses the next piece of text. Now: what exactly does it read?

How does text get into a model?

A chat is one long text

Emma sees messages. The model sees one text.

System promptThe builder’s instructions, sent before every chat. Emma never sees it.

Markers show where each message starts and ends. The text stops right where the assistant should speak, so the next token is the start of the reply.

Pieces from a fixed list

TokenA piece of text from the model’s fixed list of about 151,000. Each has a number, its id.

Common words are one token. Rare words, codes and numbers are cut into several.

The model never sees letters. It sees this list of ids, and nothing else.

Byte-pair encoding, by hand

Byte-pair encoding (BPE)Start from single letters. Again and again, glue the pair that appears most often into a new piece.

Drag the slider. “battery” becomes one piece at merge 10, because it is common.

Why not whole words? A word list built from Northbridge’s documents misses of the words in two new ones. Pieces never miss: any text can be spelt with them.

The same twelve words as NB2 exercise 2. experiments/logs/bpe.json, recomputed on the slide.

Tokens are the unit of cost

Providers charge per token in and per token out. One of Emma’s questions costs a fraction of a penny.

Today’s models also “think” before they answer, and you pay for those tokens too.

The same question takes more tokens in other languages, so it costs more.

Every turn re-sends the whole chat; an agent also sends its tools and every result. From now on, every budget is in tokens.

Section 3 of 9 · Vectors
Last sectionEmma’s question became a list of token ids. Now: an id is only a label. Where does meaning come in?

How can numbers carry meaning?

Each token becomes a vector

EmbeddingA long list of numbers stored for each token. The model looks up the row for each id.

In Qwen2.5-0.5B each row has 896 numbers. A list of numbers like this is a vector.

Nobody wrote these numbers. Training set them (Section 8).

A map of meaning

Cosine similarityHow closely two vectors point the same way: 1 = same direction, 0 = unrelated.

Words used in similar sentences end up with similar rows.

The nearest rows to “battery” and “Manchester” in the whole list of 151,000.

The 896 numbers squeezed down to 2 for the picture (principal components). Real rows from the model’s table.

Section 4 of 9 · Attention
Last sectionEach token became a vector, on its own. Now: “stores” means little without “Manchester”.

How does a word know what is around it?

Five steps with a pencil

AttentionEach token asks a question (query), every earlier token offers a label (key) and some content (value). Good matches pass on more content.

Click through the five steps. The match decides the weights; the weights mix the values.

The same four tokens as NB2 section 4. Numbers chosen by hand, two per token; a real head uses 64. The steps are the same.

Real heads, looking back

From the last position, right where the answer starts.

Causal maskA token may only look at itself and tokens before it, never ahead. That is how it can learn to guess what comes next.

Head: one attention calculation. Each block runs 14 side by side, each free to look for something different.

Position

Who approves whom depends on word order.

A weighted sum has no order.

So the model mixes each token’s position into the match.

Section 5 of 9 · 24 blocks
Last sectionAttention lets each token look back. Now: one look is not enough to answer a question.

What happens between reading and answering?

Look, then think

MLPA small network applied to each token on its own: it works on what attention gathered.
Transformer blockAttention, then MLP, each adding its result back onto the token’s vector.

Stack 24 of them and you have Qwen2.5-0.5B. Vectors keep their size, 896, all the way up.

Fig. 2. One block. “Add back the input” keeps what the token already knew; each block only adds a correction.

What would it say now?

We can stop after any block and ask: if you had to answer now, what would you say?

Early blocks give junk. “We” first comes out on top only at block of 24.

This trick is called the logit lens. Drag the slider through all 24 blocks.

Section 6 of 9 · A choice
Last sectionThe answer forms in the top block, as a vector. Now: a vector is not a word.

How does a list of numbers become one word?

Softmax

LogitA score for every token in the list: how well the top vector matches that token’s row.
SoftmaxRaise e to each score, then divide by the total. Every result is positive and they add up to 1.

Worked on the model’s real top five, at the first digit of its answer.

Picking one token

SamplingPick the next token at random, in proportion to its probability.
TemperatureDivide every score by T first. Below 1 sharpens; above 1 flattens; 0 means always take the top one.

Click the dial. Real probabilities at the first digit.

Section 7 of 9 · The loop
Last sectionOne pass through the model picks one token. Now: Emma got a whole sentence.

How does one guess become a whole answer?

Add it, run again

GenerationPick a token, add it to the end of the text, run the whole model again. Stop at the end marker.

This is the answer to the Section 1 question: a whole email is many single guesses, each one seeing all the ones before.

Drag through the answer. Orange tokens are the digits of the number.

It sounds sure. It was not.

The number was written digit by digit, like every other token.

The model gave its first digit only a chance. The sentence still reads as a plain fact.

Sample again and you get a different number. That is the spread we saw in the cold open.

The context window

Context windowThe most tokens a model can read at once: system prompt, chat so far, and its own reply. For Qwen2.5-0.5B, 32,768.

The model keeps nothing between calls. Each turn, the app sends the whole chat again.

So the context is the model’s only memory. Remember this sentence: it is Lecture 3.

Turn 1 sends
system prompt + Emma’s question
Turn 2 sends
system prompt + Emma’s question + its answer + Emma’s next message
A new chat tomorrow starts empty. Tell it the stock today, and it will not know it tomorrow.
32,768 tokens: max_position_embeddings in the model’s config.json and the model card.

Section 8 of 9 · Training
Last sectionThe machine is complete and it writes token by token. Now: we never said where its numbers came from.

Where did the numbers in the blocks come from?

Downhill, a little at a time

LossHow surprised the model was by the real next token. Low loss means it guessed well.
TrainingNudge every number a little in the direction that lowers the loss. Repeat millions of times.

We did it ourselves: a tiny GPT, trained in NB2 on Northbridge’s own documents.

What our tiny GPT learnt

Same model, same start of text: before training and after training on Northbridge’s documents.

Look at the numbersEmma’s e-mail with 5,400 is in its training text. It still never wrote 5,400. Training stores patterns, not facts you can look up: the cold open, at small scale.

Section 9 of 9 · The fix
Last sectionThe weights were frozen on the last training day, from public text. Now: back to Monday morning.

Why did it make the number up, and what fixes it?

A plausible number

The question became tokens. Nothing in them was the stock.

The weights hold patterns from public text: what a stock answer sounds like.

So it wrote a stock answer, digit by likely digit.

It did not lie. It did the only thing it does: guess the next token.
