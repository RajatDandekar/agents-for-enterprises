Section 2 of 9 · Tokens
Last sectionThe model guesses the next piece of text. Now: what exactly does it read?

How does text get into a model?

A chat is one long text

Emma sees messages. The model sees one text.

System promptThe builder’s instructions, sent before every chat. Emma never sees it.

Markers show where each message starts and ends. The text stops right where the assistant should speak, so the next token is the start of the reply.

Pieces from a fixed list

TokenA piece of text from the model’s fixed list of about 151,000. Each has a number, its id.

Common words are one token. Rare words, codes and numbers are cut into several.

The model never sees letters. It sees this list of ids, and nothing else.

How small should a piece be?

Emma’s question, cut three ways. Click to see each.

BPE: building the middle

Byte-pair encoding (BPE)A recipe for building the list of pieces.
  1. 1Start from single letters.
  2. 2Count which pair of neighbours appears most often.
  3. 3Glue that pair into one new piece.
  4. 4Repeat.

Click once per merge. Common words become one piece; rare words stay in parts.

Four Northbridge words, each counted as often as it appears; every merge is computed on the slide. Qwen ran the same recipe until it had 151,643 pieces.

The model’s vocabulary

BPE, run on a huge amount of text, left Qwen with a fixed list of pieces. That list is its vocabulary.

One question, twelve languages

Emma’s question, translated and counted. English: 14–15 tokens on all four tokenizers.

GPT-2 (2019): Tamil takes 223, 15× English: one token per byte.

GPT-4 (2023): Tamil 106, about 7×.

GPT-4o (2024, 200,019 pieces): Tamil 32, about 2×.

Qwen2.5, trained on much Chinese: Chinese 13, fewer than English. Tamil 87, about 6×.

Our own translations of Emma’s question. Counted on Modal with tiktoken (gpt2, cl100k_base, o200k_base) and Qwen2.5’s tokenizer. experiments/logs/tok_languages.json.

Why: merges follow the training text

Text is stored as bytes. An English letter is 1 byte; a Hindi, Tamil or Chinese character is 3.

BPE merges the pairs it saw most often. If a tokenizer saw little Tamil, it learnt few Tamil merges, and Tamil stays in small pieces, sometimes pieces of a single letter.

What it costs you: more tokens to pay for, a context window that fills sooner, slower replies, and often worse answers. Check your users’ languages before you set a budget.

½ marks a piece that is only part of one letter’s bytes. Cut on Modal by each tokenizer. experiments/logs/tok_languages.json.

Tokens are the unit of cost

Providers charge per token in and per token out. One of Emma’s questions costs a fraction of a cent.

Today’s models also “think” before they answer, and you pay for those tokens too.

The same question in Tamil costs up to 15× more, depending on the tokenizer (two slides back).

Every turn re-sends the whole chat; an agent also sends its tools and every result. From now on, every budget is in tokens.

How can numbers carry meaning?

Each token becomes a vector

EmbeddingA long list of numbers stored for each token. The model looks up the row for each id.

Last sectionEach token became a vector, on its own. Now: “stores” means little without “Manchester”.

How does a word know what is around it?

Why a token must look at the others

Emma’s question, as the model holds it after Section 3: fifteen vectors, each built from its own token alone.

Query, key, value

Like a library search: your question is matched against the labels on the shelves, and you read the books that match best.

QueryWhat this token is looking for. The last position asks: where, and which item?
KeyWhat each token offers to be found by. “Manchester” says: I am a place.
ValueWhat a token passes on when it is chosen: its content.
Fig. 2. Every token makes all three. Matching query with keys decides the weights; the weights mix the values. The numbers are the hand example two slides on.

Section 5 of 9 · Inside the stack
Last sectionOne attention unit let the last token find “Manchester”. Now: the real model runs many of them, in 24 blocks.

What happens between reading and answering?

Look, then think

MLPA small network applied to each token on its own: it works on what attention gathered.
Transformer blockAttention, then MLP, each adding its result back onto the token’s vector.

Stack 24 of them and you have Qwen2.5-0.5B. Vectors keep their size, 896, all the way up.

Fig. 2. One block. “Add back the input” keeps what the token already knew; each block only adds a correction.

Which tokens change?

All 100 of Emma’s tokens go through every block together, in one pass.

Attention: each token mixes in what it needs from the tokens before it, never after.

MLP: each token’s vector is reworked on its own.

Only the last position becomes the next token. The other 99 are what it reads, in every block.

Why many heads?

HeadOne attention unit, with its own query matrix. It asks one question of the earlier tokens.

One head makes one set of weights: it can look one way at a time. The last position needs several things at once.

So each block runs 14 heads side by side. The 896 numbers are split: 14 × 64 = 896. Each head writes 64 numbers, the 14 are joined back to 896, and one more matrix mixes them.

To save memory, Qwen’s 14 heads share 2 sets of keys and values, 7 heads to a set (grouped-query attention). Each head keeps its own query.

Section 6 of 9 · Logits and softmax
Last sectionEvery block changed all 100 vectors; the last one now holds the answer as it forms. Now: a vector is not a word.

How does the last vector become the next token?

Scores become chances, one token is picked

Scores to chancesThe top vector gives every token in the vocabulary a score. The scores are turned into chances that add up to 1.
PickingTake the most likely token, or draw one at random by its chance.
TemperatureA dial on the drawing. At 0, always the top token; higher, more variety.

Section 7 of 9 · Generation
Last sectionOne pass gives one token. Now: Emma got a whole sentence, with a number in it.

How is the entire answer generated?

Add it, run again

GenerationPick a token, add it to the end of the text, run the whole model again. Stop at the end marker.

So a whole e-mail is many single guesses, each one seeing all the ones before it.

Drag through the answer. Orange tokens are the digits of the number.

It sounds sure. It was not.

The number was written digit by digit, like every other token.

The model gave its first digit only a chance. The sentence still reads as a plain fact.

Sample again and you get a different number. That is the spread we saw in the cold open.

The context window

Context windowThe most tokens a model can read at once: system prompt, chat so far, and its own reply. For Qwen2.5-0.5B, 32,768.

The model keeps nothing between calls. Each turn, the app sends the whole chat again.

So the context is the model’s only memory. Remember this sentence: it is Lecture 3.

Turn 1 sends
system prompt + Emma’s question
Turn 2 sends
system prompt + Emma’s question + its answer + Emma’s next message
A new chat tomorrow starts empty. Tell it the stock today, and it will not know it tomorrow.

How we trained it

A tiny GPT: blocks, heads, numbers. It reads one character at a time.

The taskNext-token prediction, as in Section 1: at every position of 128 characters, guess the next character.
LossHow surprised it was by the real next character. Training nudges every number a little to lower it.

steps on 2 CPUs, about 7 minutes. The loss falls from a blind guess to a confident one.

Why did it make the number up, and what fixes it?

A plausible number

The question became tokens. Nothing in them was the stock.

The weights hold patterns from public text: what a stock answer sounds like.

So it wrote a stock answer, digit by likely digit.

It did not lie. It did the only thing it does: guess the next token.
