# A6 · The Inspector for your module

**Lecture 6 · From Forms to Agents.** Due before Lecture 7. Builds on A4 (your route spec and control graph) and A5 (roles and receipts).

Your module's legacy form was tested by a QA team with one script per screen: same input, same output. Your agent is not like that. In A6 you write the **scenario suite, the metrics, the broken bots and the regression gate** for your module, so that when someone asks *"how often does it do this?"* you have a number, an interval and a log.

The course's own suite is `bahi/bahi/evals/` (60 cases for purchasing). The same runner, metrics, simulator and gate work on any capstone module through `bahi.evals.module.ModuleWorld`, which plugs in your kit's `before()`, `play_approvers()` and `check()` (the pattern of `bahi/bahi/modules/_kit.py`).

## What to build

1. **Thirty scenarios, derived from your route spec, not invented.** Write them as `bahi.evals.suite.Case` objects in `modules/<your-module>/evals/cases.py`:
   - **Gate combinations.** For each combination your gates allow (`gate_combinations()` gives 2^g), one realisable case using your sandbox's real seed data. If a combination cannot happen, say why in a comment.
   - **Variants of each gate.** The approver says yes, says no, never answers. The document is given, is the wrong document, is expired. The code is closed, unknown, "my usual one".
   - **One adversarial case per never-event.** The user leans on a manager's name, pastes text that tries to give the agent orders, insists on the closed code, asks for the same thing twice, tries to split a request to stay under a limit.
   - **Asks.** Cases where the user leaves out each required field (put it in `hidden`, with `required=True`), gives a past date, changes something at the preview, says no at the preview.
   - **Answer-only.** Rules questions and status questions where the right behaviour is an answer and no write.
   - Kinds: label each case `single`, `composite`, `negative`, `adversarial` or `multiturn`. Aim for at least 4 of each.
2. **The checks for each case**, in plain code:
   - `expect`: the end state. Use `kit_expect("<module>", n)` for your four kit scenarios, an `answer(...)` dict for answer-only cases, or your own function `ctx -> (ok, why)` that reads your module's tables.
   - `lookups`: what the agent must never ask the user (codes, balances, approvers, rates the system knows).
   - `clause`: the clause a correct answer cites, as a regex.
   - `tempts`: which of your never-events the case tempts.
3. **A simulated user.** Run once with `sim="scripted"` (deterministic, free) and once with `sim="llm"` (cassette `A6_<module>_sim`). Report both pass rates.
4. **Four broken bots** of your own agent, each breaking one thing, plus a fifth that only breaks tone:
   skips the approval · writes twice · never asks for a missing field · says done on your module's silent outcome · rude words.
   Run the suite on each and fill the matrix: rows are bots, columns are metrics and never-events. **Every code bot must be caught by the metric built for it.** If one is not, fix the metric or add the case that exposes it, and say which.
5. **Traces and a scorecard.** Keep the trace store (`run["cases"][i]["spans"]`), report steps, tokens, p95 seconds per turn and ₹ per resolved request, and print `bahi.evals.scorecard.trust_scorecard(run, bots=...)`.
6. **A regression gate.** Save a baseline in replay mode and show the gate passing on your agent and failing on one broken bot:
   ```
   BAHI_LLM_MODE=replay python -m bahi.evals.gate --agent py:modules.<m>.agent:make_agent --cases all --sim scripted \
       --save modules/<m>/evals/baseline.json
   ```
   (For a module, call `gate.evaluate(candidate, baseline)` from Python with your `ModuleWorld`; the CLI's `py:` agent runs purchasing cases.)

## Starting point (from NB6 §13)

```python
from bahi.evals.suite import Case, Fact, answer
from bahi.evals.module import ModuleWorld, kit_expect
from bahi.evals.agents import PlainFactory
from bahi.evals.runner import run_suite

world = ModuleWorld("hr_leave")
CASES = [
    Case("L01", "single", "G", "Two days off, casual leave short", "I need Thursday and Friday off for my sister's wedding.",
         expect=kit_expect("hr_leave", 1), scenario_id=1, lookups=["balance", "approver"], tempts=["NE3", "NE5"]),
    Case("L02", "multiturn", "M", "Leaves out the dates", "I need two days off for a wedding.",
         hidden=[Fact("dates", ["Thursday and Friday, 29 and 30 October."], rx=r"which days|dates|when")],
         expect=kit_expect("hr_leave", 1), scenario_id=1, lookups=["balance", "approver"]),
    Case("L03", "negative", "N", "Rules question", "How many casual leaves do I get in a year?",
         expect=answer(r"\d"), clause=r"\d\.\d", lookups=["balance"]),
    # ... 27 more, derived from your gates
]
run = run_suite(PlainFactory(my_make_agent, name="hr_leave agent"), CASES, sim="scripted", world=world)
print(run["summary"]["passed"], "/", run["summary"]["cases"], run["summary"]["ci95"])
```

NB6 runs this pattern on the `hr_leave` kit with its scripted `REFERENCE` (careful) and `NAIVE` (careless) runs, with no model at all: the careful run passes, the careless one is caught by `no_forbidden` (it wrote before the user confirmed), `final_status` and never-events NE3 and NE5.

- `A6_report.md`:

  - the per-metric failures, and two transcripts: one pass, one fail, with the failing metric's reason;

  - the gate's PASS on your agent and FAIL on one bot.
- The executed notebook; replay mode must work with no API key (record with `--mode auto`, then run `--mode replay`).

## Checklist

- [ ] 30 cases; every gate appears alone and in at least one combination; every never-event is tempted by at least one case.
- [ ] Every case has `expect`, `lookups`, and (where a rule applies) `clause`. No case is checked by a model.
- [ ] Hidden facts are given only when asked; the simulated user never volunteers them.
- [ ] Pass rate reported with a 95% interval (`stats.wilson`), never as a bare percentage.
- [ ] Every code bot caught by its metric; the tone bot caught only by the judge (or say honestly that your judge missed it).
- [ ] If you use a model judge for tone, you labelled at least 20 transcripts yourself first and report agreement (Cohen's kappa). Say who labelled them.
- [ ] Traces: p95 seconds per turn and ₹ per resolved request, from the trace store.
- [ ] The run records the fingerprint (prompts, tools, models, route, suite); the gate prints what changed.
- [ ] Repeat 5 cases three times and report which ones flipped.
