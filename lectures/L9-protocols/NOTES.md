## Part 2 · MCP security (25 min)

30. **Part hero.**
31. **Four ways in.** Define *threat model*. Attacks 1 and 2 aim at the model; 3 and 4 aim at permissions.
32. **Confused deputy.**
    - The SVC_AGENT server approved Kavita's own ₹2,69,040 request.
    - The audit trail now says SVC_AGENT, so who asked is lost.
    - The fix: run each request as the token's user. It is refused.
33. **Over-broad scopes.**
    - A read-only token lists 7 tools, and a write returns insufficient_scope with 0 PRs.
    - Read and write lists 15.
    - Audience: another server's token gets 401, the right one 200. Token passthrough is forbidden.
34. **Tool poisoning.** Highlight the hidden `<IMPORTANT>` block; the tool picker shows only the first line. Then pinning: the sha256 differs, so the tool is quarantined.
35. **Injection through tool output.** Read the fake "Suresh" note. What is true: Shakti Seals is not in the master and has no food-grade certificate (§6.2).
36. **Three defences.** D0, D1 (a rule plus spotlighting), D2 (pinning plus a taint gate). Show the code; it is 10 lines.
37. **The experiment.**
    - 180 runs: 3 attack variants × 3 defences × 2 models × 10 phrasings.
    - Success is judged by Bahi's tables.
    - Quote v1 never landed, so we strengthened it once (v2). Spend $0.32.
38. **Measured.**
    - Small model: poisoning 10/10 at D0, injection v2 5/10 at D0, and 0 for both at D1 and D2 (D2 held 10 writes).
    - Flash attempted nothing at all.
39. **One attack, two hosts.**
    - A-D0: the first call emailed the attacker, and the answer never mentioned it.
    - B-D2: the writes were held, and the answer still compared both prices.
40. **What the numbers teach.**
    - The model matters.
    - Words helped in 30 small-model runs, but that is no promise.
    - Structure does not depend on the model.
    - Pinning cost the strong model its answer (0/10 utility), so a defence must tell the person why.
    - Read the four rules for Rasoi. OWASP LLM01.
