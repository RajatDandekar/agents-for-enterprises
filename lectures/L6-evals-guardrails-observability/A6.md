# A6 · See and measure one agent of yours: trace it, evaluate it, test a conversation, gate it

Lecture 6 · Observability and Evals · due before Lecture 8 (Sat 28 Nov 2026) · **100 points**

Take an agent you built in this course (your A4 or A5 agent, or Ask Northbridge if you have none) and do for it what we
did for Ask Northbridge in class. The four notebooks are your worked example, each built step by step:
`NB6a_tracing`, `NB6b_evals_deepeval`, `NB6c_multiturn_evals`, `NB6d_ragas`.

Hand in one notebook (or repository) with the code, the outputs it produced, and a short write-up (one page, plain words)
answering the questions in each part. For model calls, use your Argus key through Argus's gateway (press **Notebook key**
in Argus), or any key of your own; with neither, use the recorded runs in the notebooks and say so. Never paste a key into
what you hand in. Guardrails are not part of this assignment: they are Lecture 7's.

## Part 1 · Trace it (25 points)
1. (10) Record your agent's work as spans: one span per turn, one per call to the model, one per tool call, each with a
   name, a start, an end and its parent. Build it by hand first (NB6a, section 1), then with OpenTelemetry and the agreed
   names (`invoke_agent`, `chat`, `execute_tool`). Put the input and the output on every span, and tokens and cost on every
   model call.
2. (8) Send the spans to LangSmith or Langfuse (both have a free tier). Add the four labels to every turn: who, which
   conversation, which prompt version, cost. Include one screenshot of a trace, and read one trace back through the tool's
   API to show that the input and the output really arrived.
3. (7) Find one failure, or one odd behaviour, in a trace. Show the span that explains it and say in three sentences what
   happened and why. Say what you put in the spans and what you kept out (personal data, secrets), and how.

## Part 2 · Evaluate it (30 points)
1. (8) Read first: run your agent on 20 realistic inputs, read every trace, write a one-line note per failure, then group
   the notes into 3 to 6 categories with counts. For each category say who was wrong: the agent, the eval, a tool, the
   set-up.
2. (10) Write 10 tasks. Each has an input in a known starting state and at least one **code** check: an outcome check on
   the state afterwards, or a check on the order of the tool calls. At least four also have a **judge** criterion. For each
   judge criterion, say in one line why code cannot check it. The judge gets one criterion, the evidence, and the reply; it
   gives a reason first, then pass or fail.
3. (6) Run each task 3 times. Report pass^1, pass^3 and pass@3, name the tasks that pass some runs and fail others, and
   say what differed between a passing and a failing run of one of them.
4. (6) Label 20 replies yourself (right or wrong against the criterion). Run your judge on them. Report agreement and
   Cohen's kappa, and one change that improved the judge (or why you could not improve it).

## Part 3 · Test a conversation (30 points)
1. (10) A simulated user: a model that plays your user, given a **goal**, what the user **knows**, and a **persona**. Write
   three goals (one where the user changes their mind, one where the first message is vague) and two personas. Show one
   full conversation.
2. (12) Score whole conversations, not single replies: the **end state** (code), the **order of actions across turns**
   (code), a turn budget (code), and one criterion on the words (judge). Run all six goal × persona pairs on your current
   prompt and on one deliberately worse prompt. Report the grid.
3. (8) Read every failing conversation. For each, say whose fault it was: the agent's, the simulated user's, or the
   scorer's. Fix at least one fault that was **not** the agent's, and report the grid again.

## Part 4 · Gate it (15 points)
1. (10) A gate: a test file (DeepEval or plain asserts) that runs your most important tasks at least twice each with code
   checks only, and a workflow that runs it on every change to your prompt or tools. You may run the same command locally
   instead of on GitHub; show its output.
2. (5) Make a deliberately bad change to your system prompt (like our Thursday edit). Show the gate failing on it and
   passing on the good prompt.

## Optional (no points): Ragas
If your agent answers from documents, write four questions with reference answers and report faithfulness, context
precision and context recall (NB6d). Plant one wrong answer and one wrong search and say which numbers moved.

## How it is marked
- Each part: does it run, is it measured (not described), is the reasoning honest. A small, real, measured result beats a
  big claimed one.
- Your own bugs count in your favour when you find them and say so: our own evals were wrong more often than our agent on
  the first run, twice (the task suite, then the simulated conversations).
- Copying our Ask Northbridge results is not allowed; using our code as a starting point is encouraged (cite it).
