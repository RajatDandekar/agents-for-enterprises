# A4 · Your module's hands: 3–4 tool folders, served over MCP

**Lecture 4 · The Hands: Tools and MCP · due before Lecture 5 (Sat 14 Nov 2026, 7 AM IST)**

In Lecture 4 Ask Rasoi got its hands: Rasoi's toolbox, one tool per business activity, served over MCP in the signed-in person's own Bahi session. Now give your capstone module the same hands.

Your module kit installs on the same sandbox: `ERP(modules=["<your kit>"])`. Its raw services are black boxes: an input goes in, an output comes out. Your job is to turn them into tools a model can use safely.

## What to build

1. **Pick 3–4 business activities** from your module's "after" sentence. At least one must be a **read** and at least one a **write**. Name them the way the speaker talks, not the way Bahi names its services (`apply_leave`, not `lv_save`).
2. **Write one folder per tool**, in `my_module_tools/<tool_name>/`:
   - `tool.json`: `name` (same as the folder), `title`, `category`, `description` written for a model (what it does, what it returns, when to use it and when not), `writes`, `services`, `input_schema` (JSON Schema: a type and a description for every argument, `required`, an `enum` wherever only some values are allowed), and an `example` that passes its own schema.
   - `tool.py`: `def run(s, **args) -> dict`, calling your kit's services through `bahi.agent.tools._bahi(s, "<service>", ...)`, so a legacy error becomes `ok: false` with `error` and `next_step`.
3. **Keep the six promises** in every tool:
   1. typed inputs, checked once at the door (the toolbox does this from your `tool.json`);
   2. errors that say what to do next;
   3. every write previews with `confirm=false` and saves nothing until `confirm=true`;
   4. an idempotency key from the content (`content_key(...)`), so a retry after a lost reply never makes a second document;
   5. a receipt read back from Bahi after the write (the document's real status, with a warning in plain words for your module's **silent outcome**);
   6. the user's own permissions: the tool only ever uses the session `s` it is given.
4. **Load, lint and test** them:
   ```python
   from bahi.erp.engine import ERP
   from bahi.toolbox import Toolbox
   from bahi.course.l4 import add_tool_dir, lint_tool
   erp = ERP(modules=["hr_leave"])
   names = add_tool_dir("my_module_tools")
   print({n: lint_tool(n) for n in names})          # every list must be empty
   tb = Toolbox(erp, "KJOSHI", names=names)         # your module's speaker
   tb.call("apply_leave", {...})                    # preview, then confirm=True
   ```
   Test three things with code, not by reading: (a) your write's preview saves nothing; (b) your module's silent outcome comes back as a warning in the receipt; (c) with `erp.inject("<your save service>", "timeout_after_commit")`, calling the write twice leaves **exactly one** document.
5. **Serve them over MCP** in the speaker's session and capture the wire:
   ```python
   from bahi.toolbox.mcp import build_toolbox_server
   from bahi.mcp_server import MCPClient
   c = MCPClient(build_toolbox_server(erp, "KJOSHI", names=names))
   c.list_tools(); c.call_tool("<a read tool>", {...})
   import json; json.dump(c.wire, open("a4_wire.json", "w"), indent=1)
   ```
6. **One model round** (optional, needs a key or the replay cassette you record): `one_round(llm, MCPClientTools(c), messages)` on your module's "after" sentence. Paste the tool call it wrote.

## What to submit

- The folder `my_module_tools/` (3–4 tool folders).
- `a4_tests.py` (or a notebook section) with the three tests above, passing.
- `a4_wire.json`: one `tools/list` and one `tools/call` from your server.
- Five lines: which activities you chose and why, and one tool you decided **not** to write (and why).

## Checklist

- [ ] 3–4 tools; at least one read and one write; names in the speaker's words.
- [ ] `lint_tool` returns `[]` for each.
- [ ] Every argument has a type and a description; `required` and `enum` used where they apply.
- [ ] Each description says when to use the tool (and, for a write, that it previews first).
- [ ] Every failure returns `ok: false`, `error`, `next_step`.
- [ ] Write: preview saves nothing (checked by counting rows before and after).
- [ ] Write: a content-derived idempotency key; the lost-reply test leaves one document.
- [ ] Write: the receipt is read back from Bahi and names your module's silent outcome in plain words.
- [ ] No service account anywhere: the tools use only the session they are given.
- [ ] Served over MCP; `a4_wire.json` submitted.
