Section 7 of 15 · RAG, by eye
Last sectionPasting every document does not fit and costs too much. We must find the few passages that answer.

How does a computer find the one clause that answers Emma?

RAG: Retrieval-Augmented Generation

Search first, then let the model read only what the search found. Three words, three steps.

Retrieval

Search the documents for the few passages that answer the question.

Emma, on D: the 5 of D’s chunks closest to her question.

Augmented

Put those passages into the prompt, next to the question, each with where it came from.

Her question, then those 5 chunks: tokens.

Generation

The model writes the answer from those passages and cites them, so a person can check.

An answer that quotes §6.2 and §6.4 and names POL-PUR-001 v4.1.

Against the last sectionPasting the 648-file part read tokens and cost for each question. The whole dump, tokens, fits no model at all.

The name: Lewis et al., 2020, “Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks”.

RRF adds 1 / (60 + rank) from each list

Reciprocal rank fusion ignores the scores and uses only positions. Emma’s question on D, the six best fused chunks.

RRF score = 160 + rank in BM25 + 160 + rank in dense
60 is the RRF constant (rag.RRF_K), the same for every question. It is not the top-k from the last section, which is how many chunks we hand to the model (5 or 10).
No model in RRFChunks 12 and 1 tie at 0.032522: ranks (1, 2) and (2, 1) give the same sum. RRF has no LLM and no weights to learn. It is the six lines of rag.rrf, and it cannot read a word of the chunks.

The RRF constant decides what a top place is worth

Drag it, or switch question. Small: the top of either list wins. Large: agreement wins. It never changes top-k.

The alternative is weighted score fusion: rescale each list’s scores to 0–1 and add them as α · dense + (1 − α) · BM25, with α tuned on the golden set. The course uses RRF with the RRF constant 60 (rag.RRF_K).

Two different things, often confused

Both reorder a list. Only one of them reads the text.

Reciprocal rank fusion

Arithmetic on positions

  • In: two ranked lists. Out: one list.
  • Reads no text. No model, no LLM, nothing trained.
  • Adds 1 / (60 + rank) per list; 60 is the RRF constant.
  • Cost: a few additions.
The reranker

A cross-encoder: BAAI/bge-reranker-base

  • In: the question and one chunk, together. Out: one relevance number.
  • A transformer with million weights, trained to score pairs.
  • Not a generative LLM: it never writes text, it only scores.
  • Run on the top 20 only.

HNSW: Hierarchical Navigable Small World

Exact search compares the question with all 28,941 vectors. Fine today; slow at ten times the size. HNSW follows links instead.

Small world. Each point links to a few near neighbours, plus a few long links. Any point is then a few hops from any other.

Navigable. A greedy walk: step to whichever neighbour is closer to the question. Stop when none is.

Hierarchical. Sparse upper layers for long jumps, a dense bottom layer for the fine search: motorways, then local roads.

A toy graph of 42 points, searched by the real greedy rule. Chroma’s graph for the dump has layers; our Qdrant collection links each point to others.

A toy, not our data: points A to J and the question (the diamond). Distance here is straight-line on the picture; a real store uses cosine distance on 384 numbers.

Twelve rules, in the order we used them

Each one is a step from today, not a slogan.

Audit the corpus: files, shapes, tokens, the mess.
Collect real questions and sort them: genesis, analytical, documentation.
Set metrics and targets with the users, latency included.
Build a golden set from real questions, with gold sources.
Parse by document type; never one reader for all.
Chunk by structure, small, with each document’s header.
Pick an embedding model by measurement (domain models for medicine).
Use BM25 or hybrid search wherever codes matter.
Filter by permission before ranking, and say what was withheld.
Handle versions and effective dates explicitly.
Choose a wiki when synthesis across documents matters and the corpus changes slowly.
Measure again after every change, in CI.

The same method, four domains

What changes is what you must never get wrong.

Pharma

Codes: product and batch numbers need BM25.

Healthcare

Refuse outside the documents, always.

Banking

Wiki for products that combine many circulars.

Latency matters at the branch counter.

Legal
