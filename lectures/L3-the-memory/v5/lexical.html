idf(t) = ln(1 + N − df + 0.5df + 0.5)

N is the number of chunks, df the number that contain t.

score(q, d) = sum over the question’s tokens t of
idf(t) · tf · (k1 + 1)tf + k1 · (1 − b + b · |d| / avgdl)
one weight per (chunk, token), stored in W
  1. Count each token in each chunk: tf, and the chunk length |d|.
  2. Count the chunks that hold each token: df, then idf.
  3. The length factor and the denominator.
  4. The weight for every (chunk, token), stored once.
  5. A question: add the columns of its tokens.

RRF adds 1 / (60 + rank) from each list

Reciprocal rank fusion ignores the scores and uses only positions. Emma’s question on D, the six best fused chunks.

No model in RRFChunks 12 and 1 tie at 0.032522: ranks (1, 2) and (2, 1) give the same sum. RRF has no LLM and no weights to learn. It is the six lines of rag.rrf, and it cannot read a word of the chunks.

k decides what a top place in one list is worth

Drag k, or switch question. Small k: the top of either list wins. Large k: agreement between the lists wins.

The alternative is weighted score fusion: rescale each list’s scores to 0–1 and add them as α · dense + (1 − α) · BM25, with α tuned on the golden set. The course uses RRF, k = 60 (rag.RRF_K).

Two different things, often confused

Both reorder a list. Only one of them reads the text.

Reciprocal rank fusion

Arithmetic on positions

  • In: two ranked lists. Out: one list.
  • Reads no text. No model, no LLM, nothing trained.
  • Adds 1 / (60 + rank) per list.
  • Cost: a few additions.
The reranker

A cross-encoder: BAAI/bge-reranker-base

  • In: the question and one chunk, together. Out: one relevance number.
  • A transformer with million weights, trained to score pairs.
  • Not a generative LLM: it never writes text, it only scores.
  • Run on the top 20 only.
