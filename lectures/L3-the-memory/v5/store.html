HNSW: a graph it walks

Comparing the question with all 28,941 vectors is exact, but grows with the dump. HNSW links each vector to its near neighbours, in layers.

The search starts at the top, sparse layer, steps to whichever neighbour is closer to the question, and drops a layer when none is.

It stops early, so it can miss. We measured it: share of the exact top 10 that came back, 224 questions.

One setting, ef_search (how many candidates it keeps), fixed it. Now in rag.HNSW.

A toy graph of 42 points, searched by the real greedy rule. Chroma’s graph for the dump has layers and links each vector to up to others ( on the bottom layer).

A new model means a new index

Vectors from two models do not mix. Change the model and every chunk must be embedded again.

So the app never names a collection. It queries an alias, northbridge.

Build the new collection beside the old, run the golden set on it, then switch the alias in one atomic call. Roll back the same way.
