# A6 · Workflows and your own agent, for your module

**Lecture 6 · The Studio.** Due before Lecture 7 (Sat 21 Nov). Builds on A4 (your module's tool folders) and A5 (your loop).

At Rasoi, Kavita's Monday reorder check, Neha's goods receipt and the dealer's email each became a workflow: a path drawn once, run on Bahi with the person's own permissions, and safe to run twice. In A6 you do the same for **your module kit** (`modules/<your-module>/`): find its repeated jobs, draw them, run them, and build one small agent of your own.

## What to build

1. **Workflow 1: a repeated job with known steps.**
   - A trigger that is **not** manual: `schedule`, `event` or `form`.
   - At least three tool nodes from your module's toolbox, each with an `as` (the person whose permissions it uses).
   - One `condition` node with both ports drawn (`true` and `false`).
   - One `error` edge: what happens when a tool returns `ok: false`.
2. **Workflow 2: a job that waits or reads.** Either:
   - an `approval` node on a document that really waits for someone in your module (a wait, an approve as that person, a resume); or
   - an `llm` node that reads free text (an email, a note, a request) into named `fields`, followed by a lookup tool that turns its words into codes.
3. **Your own agent.** An `agent` node behind a `chat` trigger:
   - instructions in plain words (what it is for, what it must never do);
   - **at most six** tools, chosen on purpose;
   - a person (`as`), `may_commit` set and justified in one sentence, and `max_steps`.
4. **Run everything twice on the same sandbox.** The second run must not create a second document. If it stops instead, say where and why.

## How to run it

**Guided track (no Python beyond the notebook).** Draw the purchasing parts in the Studio (`/studio`), export the JSON, then finish the module parts as JSON in NB6 §10 and run them with `MiniEngine` and your module's toolbox:

```python
from bahi.modules._toolbox import ModuleToolbox
erp = ERP(modules=["hr_leave"])
eng = MiniEngine(erp, llm=LLM("gemini:gemini-3.8-flash", cassette="A6_hr_leave"),
                 toolbox_for=lambda user, names=None: ModuleToolbox(erp, user, "hr_leave",
                                                                   with_purchasing=["send_message"]))
run = eng.run_until_pause(eng.start(MY_WORKFLOW, {"...": "trigger data"}))
```

**Builder track (Python).** Add to `MiniEngine` what your module needs: an `event` trigger that checks your module's own state, a `set` node with small expressions, or `retries` on read-only tools. Keep the run a plain dict that saves as JSON, and show a wait surviving a save/load.

Name your cassettes `A6_<module>_*`. Record once with a key (or `--mode auto` on Modal), then prove the notebook runs in replay mode with no key.

## What to submit

- `modules/<your-module>/workflows/*.json`: the two workflows and the agent workflow, in the Studio's JSON format (`SPEC.md`).
- `modules/<your-module>/workflows/runs/*.json`: every run, first and second, as saved run documents (status, nodes, edges taken, log).
- `modules/<your-module>/workflows/REPORT.md`, one page:
  - for each job: why it is a workflow, a workflow with an LLM node, or an agent (use the two questions from the lecture: are the steps known? is the input a record or free text?);
  - what the second run did, node by node, and which tool's idempotency key made it safe;
  - your agent's three chat turns, its tool calls, tokens and ₹ (from the node's `meta`);
  - one thing you could **not** draw, and why it needs an agent.
