# A7 · Trust for your module

**Set:** end of Lecture 7, Saturday 21 November. **Due:** before demo day, Sunday 22 November, 7 AM IST.
**Feeds the rubric:** route and authority (15) and operations (15); your suite's pass rate is the scenario score (25).

You have your kit's toolbox (A4), its knowledge (A3), a harness and a workflow (A5, A6). Today you make it
trustworthy, the same way we did for Kavita's order: identity, guards, read-back, an evaluation suite with a gate,
a trace, and recovery from a lost reply.

Your kit's brief is `modules/<kit>/README.md`. Its starter tool is in `bahi/bahi/modules/<kit>/toolbox/`.
The library from the lecture is `bahi.course.l7` (`TrustLayer`, `AskRasoi`, `evals.gate`, `evals.judge`, `retry`).

## What to build

1. **Identity.** Build your toolbox for the kit's speaker, in their own Bahi session:
   `ModuleToolbox(erp, "<speaker>", "<kit>")` or `build_module_server(erp, "<speaker>", "<kit>")`. Run your kit's
   main request once as the speaker and once as `SVC_AGENT`, and show in a table what changes (status, who approved).
2. **Guards.** Subclass `TrustLayer` and add one check per never-event of your kit (they are listed in your README).
   Each refusal returns `ok=false` with `rule`, `error` and `next_step`. Show each guard refusing a real call.
3. **Read-back.** Your write tools return a receipt read back from Bahi. Trigger your kit's silent outcome and show
   the difference between what the save said and what Bahi holds. Add a reply check: your agent may not say
   "approved", "booked", "done" (your kit's words) while the document is held.
4. **Suite and gate.** Run your four scenarios with `run_module_scenario`, three runs each, with the code checks the
   kit already has. Run an LLM judge (`bahi.course.l7.evals.judge`, with your own rubric) on the same transcripts and
   explain every disagreement. Make one change (a prompt line, a tool description, a smaller model) and gate it with
   `evals.gate`: paste the verdict.
5. **Trace.** Pick one failing run. Print its trace (`agent.trace`) and say, in two sentences, which step went wrong.
6. **Recovery.** `erp.inject("<your save service>", "timeout_after_commit", 1)` and call your write tool again with
   the same arguments. Prove that the retry finds the document by its key and that there is exactly one document.
   Make the key from the content (`content_key(...)`), never from `uuid4()`.

## Submit

- Your code (the toolbox folders, your `TrustLayer` subclass, the scripts or notebook that ran everything).
- `results.json`: the suite (12 runs), the judge rows, the gate verdict, the recovery check.
- `NOTE.md`, one page: what each guard prevents, the judge disagreements, the gate verdict, the failure you traced.

## Checklist

- [ ] No write runs in a service-account session; the comparison table is in the note.
- [ ] One guard per never-event, each shown refusing, each with a next step.
- [ ] The silent outcome caught by read-back; the reply check in place.
- [ ] Four scenarios × three runs, code checks on Bahi; never-events counted.
- [ ] An LLM judge on the same transcripts; every disagreement explained.
- [ ] One change gated, verdict pasted.
- [ ] One failing trace read and explained.
- [ ] A lost reply found by its key: one document, not two.
