One change, one evening

At the end of Lecture 7 each module got one change, in the client's words: a new policy (a rule only a document knows) or a new variant (a path through the screens it never took).

The change ships as modules/<name>/CHANGE.md and demo_change.py. The file holds a fifth scenario you do not see in advance, and the code that checks it.

We tested every change against the kit's own reference run before announcing it. Details on the next plates.

# modules/hr_leave/demo_change.py (abridged) CHANGE = {"kind": "policy", "id": "HR-CIR-2026-07", "announcement": "From today, purchase staff are covered by the Diwali-run rule too ..."} DOC = """# HR Circular HR-CIR-2026-07 ...""" # add it to your docs def apply(erp): ... # the data side, if any SCENARIO = Scenario(5, "Purchase leave inside the Diwali run", "I need Thursday 5 and Friday 6 November off ...", ["Yes, go ahead."]) def check(sc, erp, before, turns): # code only: the kit's never-events still apply, plus # 5-6 Nov approved by APATIL, no unpaid day, the rule named OLD = [...] # the careful run from Friday: must FAIL NEW = [...] # the careful run after the change: must PASS NAIVE = [...] # the careless run: must be CAUGHT # the grader, on demo day: res = run_change(your_make_agent, "hr_leave", load_change("hr_leave"))

Is each change fair?

For every kit we ran five checks on Modal, with scripted agents and no model calls.

The careful run from Friday fails the hidden test, so the change is real. The careful run after the change passes, so it can be done with the kit's own services.

And nothing else breaks: the kit's four scenarios still pass with the change in place, alone and with all eight kits installed.

What the client will ask

ProofShow me the document number in Bahi, not in your chat. Who approved it, in whose session?

The silent outcomeMake it go wrong the way it did last month. What does your agent say when Bahi says SAVED?

AuthorityYour service account can approve anything. Show me that your agent cannot.

The changeWhere does the new rule live? If HR changes it again on Monday, what do you edit?

FailureBahi hangs after Save. How many documents are there now? Prove it with your key.

Money and timeWhat does one resolved request cost, and how long does the user wait? From which log?

Plus three or four questions for your own module, from question-bank.md. An honest "we did not measure that" scores better than a guess.

Graded on your logs

Six lines, the same since Lecture 1. Each line is earned by an assignment and checked on demo day.

A never-event in any scenario costs that scenario's points, however good the rest is.

The demo-day change is worth 10: 6 for the hidden test, 2 for the document in your retrieval, 2 for saying which rule applied.

Lecture 5 made new suppliers wait for Rohit's onboarding approval in the app's inbox. Lecture 6's runner only plays Rohit in Bahi. Our first run left 8 new-supplier cases waiting on a file nobody opened (49 of 60). We let Rohit decide inbox files too.

Three directions from here

More agents

Eight modules that can call each other. Kavita's leave touches Rohit's purchasing inbox already. A purchasing agent that asks the inventory agent for free stock before it orders.
Hand-offs between agents: who holds the draft, whose identity writes.

Small fine-tuned routers

The graph's typed decisions (route, gate, fill) are a narrow job. Our scorecard's decisions are labels for a small model that runs in milliseconds.
Does a small router keep 57 of 60 and bring p95 under 20 s?

More modules

Bahi has 412 screens. Each module here took three. The kit template, the nine-jobs table and the change test carry over unchanged.
